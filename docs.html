Documentação

Guia completo para instalar, configurar e usar o lean-cache com Lean 4.

1. Instalação

O lean-cache é escrito em Rust e compila com zero dependências externas (std-only).

$ git clone https://github.com/developerfred/lean-cache.git $ cd lean-cache/lean-cache $ cargo build --release $ cp target/release/lean-cache /usr/local/bin/

Requisitos: Rust toolchain, curl (para cache remoto), gzip (opcional, para compressão), lake e lean (via elan).

2. Inicialização

Dentro de um projeto Lake (com lakefile.toml ou lakefile.lean):

lean-cache init

Isso cria o diretório .lean-cache/ com a estrutura de store de objetos.

3. Build Acelerado

O comando build resolve o grafo de imports, calcula chaves de conteúdo e decide se pula o lake build:

lean-cache build MeuArquivo.lean

Se todos os módulos estão em cache hit, o lake build é pulado e os artefatos são restaurados diretamente em .lake/build/lib/lean/.

5. Arquitetura

O modelo de endereçamento é baseado em Content-Addressable Storage (CAS):

chave = SHA-256(fonte + chaves_dos_imports + versao_Lean + flags) caminho = .lean-cache/objects/<chave[0:2]>/<chave>/
  • SHA-256 puro: implementado do zero em Rust, sem dependências externas
  • Compressão condicional: arquivos ≥64 KB são comprimidos com zstd/lz4/gzip
  • Hard-link: restauração evita cópia de disco quando possível
  • Evicção LRU: comando cache gc remove entradas menos acessadas
  • Fallback local: se o remoto falhar, o build continua localmente
  • Integridade: SHA-256 verificado após download do remoto

6. Exemplos de Uso

Build inicial

lean-cache init lean-cache build src/Main.lean

Build após edição (quente)

# Edite src/Modulo.lean lean-cache build src/Main.lean

Se apenas Modulo.lean mudou, apenas esse módulo é recompilado; o resto é restaurado do cache.

Cache remoto HTTP

lean-cache remote-set https://cache.suaempresa.com lean-cache push <chave> lean-cache pull <chave>

Cache remoto S3

lean-cache s3-push <chave> lean-cache s3-pull <chave>

8. Segurança

  • Validação de chave de cache (rejeita path traversal)
  • Validação de chave S3 e URL (SSRF protection)
  • Validação de nome de módulo Lean
  • Arquivos temporários com nomes não previsíveis
  • Credenciais S3 redacted em logs
  • Erros de rede não expõem URLs ou credenciais
